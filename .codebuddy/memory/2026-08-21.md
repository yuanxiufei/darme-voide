## GPU 检测「没生效」排查（后续任务）

### 结论：不是代码 bug，是本机无 NVIDIA 独显
- 用户反馈设置页「检测本地 GPU」功能貌似没生效。
- 实测：`GET /api/v1/ai-configs/gpu/status` 返回 200，但 `isLocalMode: false`、`hardware: null`。
- 根因：本机显卡只有 `Intel(R) Iris(R) Xe Graphics`（核显），系统无 `nvidia-smi.exe` 且不在 PATH。后端 `gpu-manager.ts` 的 `getNvidiaSmi()` 执行 `nvidia-smi` 抛错被 `.catch(() => null)` 静默吞掉 → `hardware` 返回 null。
- 前端真实 GPU 卡片用 `v-if="gpu.hardware"` 控制，hardware 为 null 时不渲染，只剩「显存占用 0.0/24GB、租约状态、已加载模型」三张估算卡片 → 用户误以为功能坏了。

### 修复（体验优化）
- `frontend/app/pages/settings.vue` GPU 监控区块：在 `gpu-grid` 后新增 `v-if="gpu && !gpu.hardware"` 的 `.gpu-notice` 提示条，文案「未检测到 NVIDIA 独显（nvidia-smi 不可用）…」，让无独显状态可感知，不再静默空白。
- 新增 `.gpu-notice` 样式（虚线边框提示条）。
- 前端 HMR 更新成功，无新编译错误。
- 注：GPU 监控功能本身设计目标就是 NVIDIA 独显（配合 Ollama/SD WebUI/CosyVoice 等本地 GPU 推理），Intel 核显本机无法展示真实硬件数据属预期。

### 追加：检测不到 NVIDIA 时显存显示 0 GB（用户后续要求）
- 用户要求「检测不到就展示 0g 显存」，避免误导（原显示 0.0/24 GB 会让人以为有 24GB 显存）。
- 改动 `frontend/app/pages/settings.vue` 两处：
  1. 显存卡片 value：`gpu.hardware ? gpu.usedVRAM_GB.toFixed(1) + ' / ' + gpu.totalVRAM_GB + ' GB' : '0 GB'`
  2. `vramPercent` computed：开头加 `if (!gpu.value?.hardware) return 0`，无独显时进度条 0%。
- 后端 `GPU_TOTAL_GB = 24` 不动（它是软件估算显存池，供 evict 租约调度计算用，改 0 会破坏 availableVramGB 计算）。
- HMR 更新成功。

## 生成历史 `/generations` 404 修复（后续任务）

### 现象
- 前端设置页「生成历史」报 `GET /api/v1/generations?limit=200 404`，且响应非 JSON（`Unexpected non-whitespace character after JSON at position 4`）。
- 后端日志确认 `/api/v1/generations` 返回 404，但同页 `/skills`/`/traces/stats`/`/storage/info` 均 200。

### 根因（重要）
- `backend/src/routes/generations.ts` 与 `index.ts` 里的 `api.route('/generations', generations)` 都是**之前会话新增**的代码，磁盘上已存在。
- 但后端启动脚本 `npm run start` = `tsx src/index.ts`（**不带 watch**，不热重载），运行中的后端进程是**旧代码**启动的，未加载 generations 路由 → 404。
- 前端 `npm run dev`（Nuxt dev）会热重载，后端 `npm run start` 不会。**改了后端代码必须手动重启后端**。

### 修复
- 杀掉监听 5789 的旧进程（`Get-NetTCPConnection -LocalPort 5789` 找 PID → `Stop-Process`），重新 `npm run start`。
- 重启后 `/api/v1/generations?limit=200` 返回 200，聚合 image_generations + video_generations 数据正常。

### 关键教训
- 开发时建议后端用 `npm run dev`（`tsx watch`，改代码自动重启），否则每次改后端都要手动杀进程重启。本次启动用了 `npm run start` 是历史遗留习惯。
