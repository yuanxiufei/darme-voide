### 关键教训

1. **转述的数量级普遍失真**：Seedance2「20 万+」实为 8100+（50GB 是配套视频）；Rapidata 被称"非常适合"实为 ~200 条。
2. **星数会骗人**：`geekjourneyx` 78★ 却 0 条数据；`Semonxue` 仅 14★ 却有 3097 条。
   → **核仓库必须看 `size` (KB) 和真实文件树，不能看 star。** 4 KB / 24 KB 的体积直接暴露空壳。
3. **别被仓库体积吓退**：Semonxue 4.88 GB 全是 `static/` 的封面与视频，
   `content/` 是纯文本 → `git clone --sparse` 只取 `content data`。
   Seedance2 的 50 GB 同理 → **只下 `metadata.jsonl`(37.6MB)** 就拿到全部提示词。
4. **许可证是硬约束**：TIP-I2V 是 CC BY-NC（禁商用），**不得进产品**；
   Seedance2 是 CC BY 4.0（可商用需署名）；Semonxue **无 LICENSE** → 仅内部参考。

### 提炼结论（已写入 skill）

**核心判断：两批语料属于不同创作人群，写法不冲突，不能互相推翻。**

- Seedance2（平台通用短视频）→ **散文式多段**为主（实测时间码仅 14%，作分段标题仅 3%）。

**三条实测修正**：
1. 「一镜到底」仅 323/8755（≈4%）→ 从 §6.1 的**固定骨架降为可选项**。
   真正高频的是 旋转 2571 / 手持 2563 / 环绕 1225 / 推进 1049 / 定格 1024 / 跟随 1003。
2. 「杜绝美化」仅现 2 次 → 行业通用写法是**部位清单式锚定**

3. **反 AI 感词族**（skill 原先完全没覆盖）：`不完美的自然构图` / `自动对焦不完美` /
   `逼真的环境瑕疵` / `可信的瑕疵` / `轻微手持不稳` / `自然高ISO颗粒` / `自动对焦呼吸`。
   → 这类**可控缺陷**比堆 `8k, ultra detailed` 更能压掉塑料感。

其它可复用写法：独立「负面提示：」末段（顿号并列反例）、情绪段 `《Mood》是…`、
**具体焦段 + 器材缺陷**（`200mm–400mm 视角` + `浅层自动对焦不一致`）优于笼统「电影感」、

## 按用户要求「把整体项目方面与项目功能融合在一起」→ 画风体系全链路收口

用户要求把已建立的**画风体系 + 语料提炼成果**从「文档 / skill 层」真正贯通到项目的**生成功能**。
排查后发现两处结构性断链（不是文档问题，是代码没接上）：

### 断链 1：画风只在「角色/装备/道具/表情」图像链路生效

其余链路都是把**落库 key 直接拼进 prompt**，`DRAMA_ART_STYLE_MAP` 的四段词表从未参与：

| 链路 | 改前写法 | 后果 |
|---|---|---|
| 场景图 | `${key} visual style` | 等于没画风 |
| 分镜静帧 | `${key} visual style` | 等于没画风 |
| 宫格图 | `${key}`（直接拼） | 等于没画风 |
| 视频 | `${key} cinematic style` | 水墨/动漫被强行拉向写实电影 |
| 视频负面 | 恒定 `VIDEO_NEGATIVE` | 无画风对立词，动漫/真人/三维会混 |

且 `videos.ts` / `images.ts` / `auto-pipeline.ts` **传的是 `dramaStyle: undefined`** → 视频链路画风完全断路。
截图/宫格/场景的负面词也恒定，与正向画风不配套。

### 断链 2：解析逻辑被复制了 3 份

`characters.ts` / `dramas.ts` 各存一份 `getGlobalArtStyle` 私有副本，`characters.ts` 还有私有
`getEffectiveArtStyle` / `getDramaStyle` → 画风体系一改要改多处，极易漏。

### 改法：在 `prompt-utils.ts` 建「画风收口层」（唯一入口）

- 解析：`resolveArtStyleKey(...)`（纯函数，**只认合法 key，脏值跳过而非透传**）、
  `getDramaArtStyle` / `getGlobalArtStyle` / `resolveEffectiveArtStyle(dramaId, charStyle?, dramaStyle?)`
  （`dramaStyle ?? getDramaArtStyle(dramaId)` 短路，避免重复查库）。
- 正向后缀：`buildSceneArtStyleSuffix` / `buildStoryboardArtStyleSuffix` / `buildVideoArtStyleSuffix`。
- 负向后缀：`buildSceneNegativePrompt` / `buildStoryboardNegativePrompt` / `buildVideoNegativePrompt`
  （通用负面 + `DRAMA_ART_NEGATIVE_MAP` 画风对立词），与正向成对使用。
- 语料成果落地：`IMPERFECTION_ANCHORS`（反 AI 感词族）+ `PHOTOREAL_ART_STYLES` 白名单，
  **仅写实向画风注入**；`VIDEO_MOTION_BASE` 抽掉写实专属词。

### 关键设计判断（可复用）

1. **视频必须与静帧拆开**：静帧收口词 `cinematic illustration style` / `soft cinematic lighting`
   会把动漫、水墨拉回写实插画 → 视频单独用中性收口 `VIDEO_STYLE_TAIL`，命中画风时**不再追加
   `VISUAL_STYLE_MASTER`**；未命中画风（`undefined`）时完全回退历史默认，保证向后兼容。
2. **反 AI 感词族要按画风白名单注入**：写实向注入能压塑料感，注入到水墨/动漫会直接破坏风格。
   「可控的现实缺陷」是**画风相关**的，不是通用优化项。
3. **后端注入画风 + skill 禁止 agent 输出画风词 = 不会重复叠加**。这条约定让 auto-pipeline
   可以放心地把 agent 生成的 prompt 直接 `+ buildVideoArtStyleSuffix(artStyle)`（每次提交现算、
   不落库，因此不会累积）。若哪天 skill 放开画风词，这里必须改成幂等校验。
4. **`grid.ts` 两处 `let dramaStyle = ''` + 查库代码长得几乎一样**，第一次 replace 只命中一处
   （因为 old_str 含 `// Get drama style` 注释）→ 改这类重复代码**必须 grep 确认全部命中数**。

### 改动清单（backend，全部 tsc 通过）
