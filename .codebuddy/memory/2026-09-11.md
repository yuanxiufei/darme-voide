## 剧集工作台「点生成/保存就跳转」根因（2026-09-11 已修）
- 现象：`/drama/[id]/episode/[episodeNumber]` 各步骤（原始内容/AI改写/提取/音色/分镜）点生成后，画面会跳到别的步骤。
- **不是路由跳转**：全项目改 URL 的地方只有 `goBack()` 和两处 `asset-card clickable` 的 `@click="$router.push(...)"`，而卡片内的生成/编辑按钮都已带 `@click.stop`；页面无 `<form>`（唯一 `<a>` 是带 `download` 的成片下载），`useApi`/`useAgent` 里均无 navigateTo / location 跳转。
- **真实根因**：`refresh()` 里无条件重算 `scriptStep`（`if (epHasSbs) scriptStep=4 else ...`），而 `refresh` 被所有生成/编辑操作当完成回调复用（`onMounted` 与 30+ 处 `await refresh()`）。于是「在第 2 步提取点生成 → 已有分镜 → scriptStep 被设成 4 → 跳到分镜」。
- 视觉放大：`.main`/`.content-panel` 是 `overflow: hidden`，真正的滚动容器（`.script-preview`/`.extract-list`/`.voice-stage`/`.prod-content`/`.split-layout`）都在 `scriptStep`/`prodTab` 的 `v-if` 子树内，步骤一变容器重建 → scrollTop 归零，用户感知为"页面跳走"。
- 修复：新增 `let stepInitialized = false`，把步骤定位包进 `if (!stepInitialized) { ... stepInitialized = true }`，仅首次加载按已有产物定位；后续 refresh 保留用户当前步骤（改写完成的显式 `scriptStep.value = 1`、跳过改写的 `= 2` 不受影响）。
- 经验：**被多处复用的 `refresh()`/load 函数里不要写"UI 定位/导航"副作用** —— 它会在每次生成、轮询（视频合成 poll 每 4s 一次）时重放，覆盖用户上下文。此类副作用只应在首次加载时执行一次。

## 续：彻底解耦 + 实测验证（2026-09-11）
- 最终方案：新增 `initScriptStep()`，把步骤定位**完全移出 `refresh()`**，只在 `onMounted` 里 `await refresh()` 后调用一次。中途试过的 `let stepInitialized` 标志被废弃 —— 它是 script setup 里的普通变量，HMR / 组件重建会重置为 false，保护会失效。
- 同时修掉 refresh 的另外两处状态覆盖：
  1. `selectedSb` 陈旧引用：`sbs.value` 每次是全新对象数组，原来 `if (len && !selectedSb) selectedSb = sbs[0]` 会让选中项一直指向旧对象（详情面板不更新、选中高亮丢失）。改为按 id 重绑定：`(keepSbId ? sbs.find(s=>s.id===keepSbId) : null) || sbs[0] || null`。
  2. 配乐参数：新增 `bgmDirty`，模板 3 个输入 `@input="markBgmDirty"`、`onPickBgm`/`clearBgm` 置脏、`saveBgm` 成功后清脏；refresh 中 `if (!bgmDirty.value)` 才用服务端值覆盖，避免用户调好的音量/淡入淡出被任意生成操作打回原值。
- 侧栏结构（实测）：`nav button` = 12 个主步骤（原始内容/AI改写/提取角色场景/分配音色/角色形象/场景图片/分镜拆解/镜头图片/配音生成/视频生成/视频合成/拼接导出）；`aside button` 共 18 个 = 12 主步骤 + 5 个 `sidebar-jump-dot`（当前 section 的子步骤，随 `activeSubStepKey` 换组）+ 1 个 `.refresh-btn`（`@click="refresh"`，位于 aside 最后一个）。所以"步骤跳"会在左侧两处 + 中间内容区同时体现。
- **实测验证法（可复用）**：`execute_command` 跑 playwright-cli 常被转后台拿不到 stdout → 用 `playwright-cli eval "..." *> .pwN.log` 落盘，再用 `read_file` 读。要点：① 输出只用**纯 ASCII**（返回 active 按钮的索引而非中文文本），规避 PowerShell 中文乱码；② 用 `document.querySelectorAll('nav button')[i].click()` 按结构定位，避免中文选择器；③ 断言索引：`RELOAD_nav=6`（进页面自动定位到分镜）、点 nav0 后 `=0`、点 refresh 后仍 `=0` 且 url 未变，三点全过才算修复生效。
- **重要踩坑**：**不要一边改该文件一边跑浏览器点击测试** —— Vite HMR 会重建组件、重跑 onMounted、重置 setup 内普通变量，导致出现"修复无效"的假象（曾误判一次 `STEP2_nav=6`）。改完文件等 HMR 稳定后再测。
