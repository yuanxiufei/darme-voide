## 阶段 4 收尾：ModelScope 大文件签名 URL 兜底

问题：魔搭来源原用 `/models/{repo}/resolve/{rev}/{path}` 302 直链，部分 LFS 大文件可能被拦截/失败。

方案：后端 `localModels.ts` 新增 `getModelScopeDownloadUrl(repo, revision, filePath)`，调用 `https://modelscope.cn/api/v1/models/{repo}/repo?FilePath=..&Revision=..` 取 `Data.Url` 签名下载地址；下载循环中 `source==='modelscope'` 时优先用签名 URL，失败回退 `/resolve/` 直链。

CLI `scripts/model_manager.py` 未改多源：其 `configs/models.json` 中 `runtime=comfyui` 的 `url` 为硬编码完整地址，用户可自行改成 hf-mirror 地址，与 Web UI 三源闭环是两套独立系统。

验证：`npx tsc --noEmit` 通过（exit 0），localModels.ts read_lints 0 错误。

## 阶段 5：下载健壮性（断点续传 + 跳过已存在 + 源偏好记忆）

后端 `localModels.ts` 下载循环改造：
- 临时文件由随机 `.tmp-{uuid}-{name}` 改为固定 `{outPath}.part`，中断后保留供续传
- 目标文件已存在且 `size >= f.size` → 跳过（`file_done` 带 `skipped:true`）
- `.part` 已存在且完整 → 直接 rename 完成
- `.part` 部分存在 → fetch 加 `Range: bytes={partSize}-`，写流 `flags:'a'` 追加；服务器返回 206 才视为续传，200 则 `'w'` 重写
- 失败不再删除 `.part`（保留续传）
- `file_start` 事件带 `resumed` + `downloaded`（续传时=partSize）

前端 `settings.vue`：
- `hfSource` 持久化 localStorage（key `darme.hfSource`），`loadHfSource()` 初始化 + `watch` 回写
- 进度文案区分：`file_start` 断点续传提示、`file_done` 「已存在，跳过」

验证：`npx tsc --noEmit` 通过（exit 0），settings.vue read_lints 0 错误。

## 阶段 5 修复：断点续传/跳过时进度统计 bug

问题：`overall` 只累计「本次新下载」的字节，断点续传/跳过/rename 三处未计入已存在字节，导致前端进度条从 0% 起、有跳过文件时永远到不了 100%。

修复（`localModels.ts` 下载循环三处补 `overall +=`）：
1. 跳过已存在 → `overall += existing`
2. `.part` 完整 rename → `overall += partSize`
3. 续传 206 → `overall += partSize`（仅 isPartial 时；200 重写时旧数据作废不计）

验证：`npx tsc --noEmit` 通过（exit 0），localModels.ts read_lints 0 错误。
