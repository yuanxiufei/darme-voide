## 字节回退（`byte_fallback`）实现 —— 顺带推翻上一轮的拒绝理由（第十二项 ✓ 2026-09-21）

### 上一轮的拒绝理由本身是错的 ✗（教训值钱）
上轮写「实测参考实现该配置下**没走**字节回退 ⇒ 语义未核清 ⇒ 拒绝」✗ ——
⚠️ 那次实测**少了前置条件** ✗：词表里**没有** `<0xNN>` 字节 token ✓✗（没有字节 token 当然回退不出去 ✓）。
补上字节 token 再测 ⇒ **真走回退** ✓（`'中'` ⇒ `<0xE4><0xB8><0xAD>` ✓）。
⇒ ⚠️ **「实测过」也要写明前置条件** ✗：否则一个残缺的复现会被当成「语义不明」的证据 ✓✗。

### 核清的规则（全部实测 ✓）
1. **逐字节判据**：该字符 UTF-8 的**每个**字节都要有 `<0xNN>` token ✓ —— 缺**一个**就回退不了 ✓
   （词表只有 `<0xE4>` 时 `'中'` 出 `unk` ✓ 而不是只出 `<0xE4>` ✓✗）；
2. ⚠️⚠️ **段级判据**（最容易写错 ✓）：按「**连续未知段**」决定 ✗ 不是按字符 ✗ ——
   段内**每个**字符都能展开 ⇒ 逐字符展开 ✓；只要有**一个**展开不了 ⇒ **整段**合成一个 `unk` ✓✗。
   实测：`'中中'` ⇒ 6 个字节 ✓；`'中x'` ⇒ 整段一个 unk ✓（`'中'` **也不**展开 ✓）；
   `'中中x'` ⇒ 整段一个 unk ✓；⚠️ **词表能匹配的字符照常保留** ✓（`'a中x'` ⇒ `[▁, a, unk('中x')]` ✓）
   ⇒ 段 ≠ 整片 ✓；
3. 字节 token 名只认 `<0x` + **两位十六进制** ✓（`<0xZZ>` 不算 ✓）；
4. 字符本身在词表 ⇒ 走正常 token ✓（字节只是兜底 ✓）；字节 token **不并入 `unk`** ✓；
5. `fuse_unk=False` ⇒ 回退不了的段**逐字符各一个** `unk` ✓（与不回流时的口径一致 ✓）。

### 顺带修掉一个 Metaspace 的既有偏差 ✗
`prepend_scheme="always"` 的补前缀判据要**连 `replacement` 一起看** ✗：
首字符既不是空格、**也不是 `replacement`** 才补 ✓（第一版只看空格 ✗ ⇒ 输入 `"▁"` 被补成 `▁▁` ⇒ 出两个 token ✓✗，
参考只出**一个** ✓）。实测对照：`"▁"`⇒`['▁']` ✓、`"▁▁a"`⇒`['▁','▁a']` ✓。

### 判定/接线
