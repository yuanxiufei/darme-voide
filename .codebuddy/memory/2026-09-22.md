## 反量化（fp8/int8 → 可算精度）—— 关键路径上的真缺口（2026-09-22 第三段）

### 为什么这是**关键路径** ✗（不是锦上添花 ✓）
目标主权重是 **19.53 GiB 的 fp8** ✓（50 层 × [5376 / 14336] ✓ —— bf16 会是 ~39 GiB ✗）。
而 `load_module_weights` 原来的做法是 `tensor.to(dtype)` ✓✗ ⇒ **fp8 张量直接 cast = 把尺度丢掉** ✗：
得到一个**看着正常、数值全错**的模型 ✓✗，而且 `load_state_dict` **照单全收不报错** ✗✗
（症状要到出片才发现「画面是噪声」✓ —— 正是本仓最怕的那类失败 ✓）。

### 新模块 `engine/quant.py`（纯函数 ✓ 只依赖 torch ✓）
- **布局按形状判** ✓ 不按文件名猜 ✗：标量 ⇒ per-tensor ✓、`(out,)` ⇒ per-row ✓、`(in,)` ⇒ per-col ✓、
  与权重同形 ⇒ 逐元素 ✓；**对不上任何一种 ⇒ 拒绝** ✓（典型是**块量化** ✓ group size 在随附 json 里 ✗）；
- **两种方向** ✓：`*.scale|scales|weight_scale` ⇒ 乘 ✓；`*.weight_scale_inv` ⇒ **除** ✓。
  ⚠️⚠️ **长后缀优先** ✗：否则 `weight_scale_inv` 会被 `weight_scale` **前缀命中** ✓✗ ⇒ 把「除」当「乘」✓✗
  （自检 ③ 专门钉这条 ✓）；
- **拒绝**（不猜 ✗）：块量化形状 ✓ / 分组量化（`qzeros`/`g_idx` ✓）/ 缺配套 scale ✓ / scale 含 0 ✓；
- 配套 scale 张量**不进模型** ✓（模型里没有 `.scale` 键 ✓ —— 留着只会变 unexpected ✓）；
- 全在 **float32** 里算 ✓ 再 cast ✓（scale 往往是小数 ✓ 低精度里算会掉精度 ✓）。
