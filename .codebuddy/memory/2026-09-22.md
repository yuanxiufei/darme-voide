## 潜通道数的**跨来源校验**（新守卫 ✓ 2026-09-22 下半场）

### 守的是什么坑 ✗（读权威清单时发现的）
`PENDING_PARTS` 那条「仍留给真权重的一步：按元数据复核 `patch_size` ✗」后面藏着一条**静默错**路 ✗✗：
主干推的 `latents_dim` = `video_patch_proj.weight` **列数 ÷ patch 乘积** ✓ —— 而 `patch_size` 只能
**供方自述** ✗（权重里没有 patch 痕迹 ✗）⇒ **给错但能整除**时（例：真值 `(1,2,2)` 给了 `(1,1,2)` ✓）
会推出 **错的 `latents_dim`** ✓✗，而 `video_patch_proj` 列数 ✓ 与输出头行数 ✓ **两边形状都还自洽** ✓✗
⇒ `load_weights` **装得进去** ✓✗ ⇒ 只有**画面不对** ✗✗（本仓最怕的那种）。
原先只能在**解码**时由 `VAE._check_latent` 的形状错兜住 ✗ —— 报的是「潜变量形状应为 (B,24,…)」✗，
**指不到真因** ✗。

### 独立来源：VAE 自述的潜通道数 ✓
`vae.py` 的事实表**自己就写着**「24 个均值/标准差 ⇒ 潜通道 24 ✓（与 `dit.H3_SHAPE_FACTS` 的
`latents_dim` 一致 ✓）」✓ —— 即**两边本来是同一个事实** ✓，只是从没在挂载期核过 ✗。
（音频那档同理：`H3_AUDIO_VAE_FACTS["latent"]` 的 32 ✓ ↔ 主干 `audio_latents_dim` ✓；
测试夹具的注释里也早写着「音频 VAE 的 `latent_channels` **必须** = 主干的 `audio_latents_dim` ✓」。）

### 实现（`TorchBackend._check_latent_channels` ✓）
- 两档分开报 ✓：视频（`latents_dim` ↔ 视频 VAE `latent_channels` ✓）/ 音频（`audio_latents_dim` ↔
  音频 VAE ✓）；**对不上 ⇒ 当场 `TorchBackendUnavailable`** ✓（不静默取其中一个 ✓）。
- 报错**可行动** ✓：视频那档点名「大概率是显式 `patch_size` 与权重不符 ✓」并**印出当前 patch_size** ✓；
  ⚠️ 音频那档**不许**把锅推给 `patch_size` ✗（音频侧不乘 patch ✓）—— 自检 55″ 钉住这点 ✓。
- ⚠️ **挂载顺序两向都守** ✗：挂 VAE 时查一次 ✓ + `load_weights` 的 H3 分支里**再查一次** ✓
  （先挂 VAE 那次还没有形态 ⇒ 没有可比事实 ⇒ 不报 ✓ 不是漏 ✓）。
- ⚠️ `load_weights` 里校验失败 ⇒ **中止装载 + 不污染模块** ✓（回滚 `_model`/`_config`/`_form` ✓ ——
  本仓在反量化那条上定的规矩 ✓；否则 `latentMode` 会按「装好了」自述 ✗）。
- `describe()` 里给**不抛**的版本 ✓（`latentChannelCheck` ✓ —— `describe()` 任何时候都得能调 ✓）；
  核过要能自证 ✓（两条的 `agrees` 与两边各自的数都报出来 ✓）。

## 跨来源校验扩到**四个字段**（2026-09-22 下半场之二）

上一轮只守了「潜通道数」✓ —— 顺着同一思路把**同一事实有两个来源**的地方全扫了一遍 ✗，
又抓到三处（都是「装得进去、出来不对、**不报错**」✗✗）：

### ① 视频**空间倍率** ✗
`init_dual_latents` 用的是 **事实表**的 `vae.H3_VIDEO_VAE_FACTS["vaeScale"]=16` ✓ 算潜尺寸 ✓，
而**首帧编码 / 参考视频编码**（`_dual_keyframes` / `condition_first_frame` ✓）用的是
**`self._vaeConfig.spatial_scale`** ✓ ⇒ 挂一个别的倍率的 VAE（例：4 层 ⇒ 8 ✓）⇒ 潜尺寸按 16 算 ✓、
解码按 8 放 ✓✗ ⇒ **出来的画面尺寸与请求的不是一回事** ✓✗（**不报错** ✗✗）。
（顺带说明：这两处**本来就不一致** ✗ —— 现在被守卫钉成必须相等 ✓。）

### ② 音频**帧率** ✗✗（最阴的一条）
潜帧数按 `geometry.AUDIO_LATENT_HZ=40` 算 ✓，而解码端按**音频 VAE 自己的 `hop`** 展开 ✓✗
⇒ 挂一个 `latents_per_second ≠ 40` 的音频 VAE（例：`sample_rate=16000` + 同一组 rates ⇒ 20 ✓）
⇒ **wav 时长就是错的** ✓✗（**不报错** ✗✗）。

### ③ 音频**声道** ✗
`init_dual_latents` 按 `geometry.AUDIO_LATENT_CHANNELS=2` 造立体声那一维 ✓，
而解码端要的是 `AudioVAEConfig.stereo_channels` ✓ ⇒ 不等就形状对不上 ✓（这条会响 ✓ 但仍晚 ✗）。

### 实现（`_check_attached_vaes` ✓ —— 由 `_check_latent_channels` 改名扩写 ✓）
- 配对表 `(流, 自述字段, 期望值, 期望值的来源, 对不上的「大概率是」✗)` ✓，四/五个字段一起核 ✓；
- H3 形态核四条（视频 通道+倍率 ✓ / 音频 通道+声道+帧率 ✓）；**DiT 形态**只核
  `spatial_scale ↔ config.vae_scale` ✓（H3 那几条不适用 ✗ —— 别把守卫做过头 ✗）；
- 报错逐条**说清后果** ✓（「画面尺寸不是一回事」/「wav 时长错」✓）而不是一句「不一致」✗；
- `describe()` 的键名从 `latentChannelCheck` 改成 **`vaeCheck`** ✓（旧名残留已 grep 清 ✓）。

### 自检（`engine_dual_stream_test` 63 → **66 项** ✓）

**56″ 倍率 8 ✗ ⇒ 报（点名「不是 H3 那一族」✓）** / **56‴ 帧率 20 ✗ ⇒ 报（点名「时长」✓）** /
